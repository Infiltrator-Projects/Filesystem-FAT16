# Shared localisation

Libraries owns the platform-neutral localisation engine used by the project family. Applications compile immutable translation catalogues into their binaries and use `InfiltratrI18n` for lookup and interpolation; no JSON parser, gettext runtime, Foundation, Win32 or GLib dependency is required by the engine.

The engine accepts locale tags such as `en-AU`, `de-DE` and `de_AT.UTF-8`, normalises underscores and common encoding suffixes, and resolves values in this order: exact requested locale, same-language catalogue, exact configured fallback locale, same-language fallback catalogue, then the translation key itself. Returning the key for a missing translation makes catalogue gaps visible during development rather than rendering blank UI.

Visible sentences should use stable semantic keys such as `nav.vehicle` or `scan.modules_found`. Technical identifiers such as DTCs, CAN IDs, UDS service numbers, DIDs and protocol names are data and are not translation keys. Named placeholders are formatted with `infiltratr_i18n_format`, allowing translators to reorder inserted values rather than concatenating English sentence fragments.

Platform code is responsible only for discovering the user's preferred locale and for optional language-selection UI. Product repositories own their product-specific catalogues; reusable strings belong with the lowest shared layer that owns the corresponding behaviour.
