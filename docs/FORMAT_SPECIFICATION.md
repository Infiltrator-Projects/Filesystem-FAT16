# FAT16 original-format technical reference

This supplement expands the existing historical manual. It distinguishes normative media structures, historical compatibility profiles, and implementation qualification. It takes precedence over simplified descriptions in the manual where details differ; the cited original specifications remain authoritative. No additional implemented operation is claimed.

## FAT16 and FAT16B historical chronology

The FAT family began with Microsoft's 8-bit table in 1977-78 and Tim Paterson's 12-bit QDOS in 1980. IBM PC DOS 3.0 and MS-DOS 3.0 (August 1984) introduced 16-bit allocation for the PC AT's larger hard disks. The original FAT16 still used a 16-bit total-sector field: at 512 bytes/sector, fewer than 65536 sectors, just under 32 MiB. MBR 0x04 identifies the historical small partition. Compaq MS-DOS 3.31 (November 1987) introduced the 32-bit total-sector field (FAT16B/BigFAT); DR DOS 3.31, PC DOS 4.0, MS-DOS 4.0 and OS/2 1.1 followed in 1988. MBR 0x06 is common for FAT16B; 0x0E denotes LBA FAT16, introduced with Windows 95-era access. These are not new FAT entry widths. When geometry is valid, a modern FAT16 engine can interpret the original or later BPB; no blanket pre-DOS compatibility is implied.

## OEM sectoring, BPB evolution and volume limits

Some OEM DOS versions bypassed the 16-bit sector-count limit by grouping physical sectors into larger logical sectors (sometimes 8192 bytes), with distinct partition identifiers: 0x08 Commodore, 0x11 Leading Edge, 0x14 AST, 0x24 NEC, 0x56 AT&T, 0xE5 Tandy, 0xF2 Sperry/Unisys. Interpret logical geometry explicitly, never assume that the BPB sector size equals a physical device sector. DOS 3.2's historical field at 0x1E differs from the DOS 3.31 32-bit field at 0x20. Historical extended/logical partitions introduced with DOS 3.2/3.3 are partition-layer constructs, not FAT data structures. CHS fields are advisory for LBA partitions. At 65524 data clusters and 32 KiB per cluster, data area = 2,147,090,432 bytes; 64 KiB yields 4,294,180,864 bytes. The complete volume includes metadata. 64 KiB and larger clusters have limited OS compatibility; early DOS and later Windows support differs. The 32-bit file-length field is bounded at 4 GiB-1 but the volume may constrain files further. Historical FAT16+ proposals and NT/EDR-DOS large-cluster variants require separate qualification.

## 16-bit links, status bits and root geometry

Each FAT entry is a little-endian word at byte 2*n. Free=0x0000; reserved=0x0001; normal successor=0x0002..0xFFEF; reserved=0xFFF0..0xFFF6; bad=0xFFF7; EOC=0xFFF8..0xFFFF. FAT[0] normally 0xFF00 | media; FAT[1] normally 0xFFFF. In supported status conventions FAT[1] bit 15 is clean shutdown, bit 14 is no recorded I/O error (clear indicates adverse state); these flags are not general transaction commits. The FAT16 classification interval is 4085..65524 data clusters; conservative formatting avoids cutover and marker-valued cluster IDs. Some historical readers admit nonstandard high values; do not write such media without an explicit qualified profile. Root directory is a fixed table; with 512 root entries and 512 bytes/sector it occupies 32 sectors. An empty root slot is not a free data cluster. MBR type 0x04/0x06/0x0E does not override BPB-derived type.

## FAT12/FAT16 extended BPB and profiles

For DOS 4.x-style FAT12/16 EBPB: hex offset:size 0x24:1 drive, 0x25:1 reserved, 0x26:1 signature (usually 0x29), 0x27:4 volume ID, 0x2B:11 volume label, 0x36:8 type string; boot code follows. These fields are not present in all older disks. DOS 2.0 introduced core BPB fields; DOS 3.0 introduced further geometry and DOS 3.31 established 32-bit sector-count/hidden-sector fields. Some older disks use alternate boot placement or no valid BPB. Distinguish normative modern layout from each historic profile. Do not interpret historical EA data at directory offset 0x14 as FAT32 high cluster bits. Root entries are fixed at format time; root occupies ceil(32*root_entries/bytes_per_sector) logical sectors. Validate FAT copies before reading/writing.

## Common BPB and region arithmetic

Hex byte offset:size (modern DOS/EFI layout): 0x00:3 jump; 0x03:8 OEM name; 0x0B:2 bytes/sector; 0x0D:1 sectors/cluster; 0x0E:2 reserved count; 0x10:1 FAT count; 0x11:2 root entries; 0x13:2 TotSec16; 0x15:1 media; 0x16:2 FATSz16; 0x18:2 sectors/track; 0x1A:2 heads; 0x1C:4 hidden sectors (DOS 3.31 layout); 0x20:4 TotSec32. Boot signature bytes 55 AA at 0x1FE. Interpret logical-sector sizes and power-of-two cluster sectors with checked arithmetic. root_sectors=ceil(root_entries*32/B); fat_sectors=FATSz16 if nonzero else FATSz32; total=TotSec16 if nonzero else TotSec32; first_data=reserved+FAT_count*fat_sectors+root_sectors; cluster_count=floor((total-first_data)/sectors_per_cluster). Reject overflow, underflow, truncated media and FAT capacity below cluster_count+2 entries. Cluster n sector=first_data+(n-2)*sectors_per_cluster, relative to volume; add partition offset only in whole-device host translation. CHS translation is historical: LBA=((cylinder*heads)+head)*sectors_per_track+sector-1. FAT type is based on count, not the textual label or partition ID. Stay at least 16 clusters away from type cutovers when formatting for broad legacy compatibility.

## Directory record - exact 32-byte layout

Hex offset:size: 0x00:11 OEM short name (8 base + 3 extension, spaces padded); 0x0B:1 attributes; 0x0C:1 NT case flags (base lowercase bit3, extension bit4); 0x0D:1 create 10ms increment (0..199); 0x0E:2 create time; 0x10:2 create date; 0x12:2 last access date; 0x14:2 first-cluster high word on FAT32, reserved or historical EA handle on FAT12/16; 0x16:2 modification time; 0x18:2 modification date; 0x1A:2 first-cluster low word; 0x1C:4 file size. Attributes: 0x01 read-only, 0x02 hidden, 0x04 system, 0x08 volume, 0x10 directory, 0x20 archive; 0x0F identifies LFN; upper bits reserved. First byte 0x00 means end, 0xE5 deleted, 0x05 encodes initial OEM 0xE5. Directory sizes are normally zero; traverse chains. Dot points to self; dot-dot uses zero for root parent. Root volume labels are metadata, not ordinary files. Timestamp date bits 0..4 day, 5..8 month, 9..15 year minus 1980; time bits 0..4 seconds/2, 5..10 minute, 11..15 hour. Representable years 1980..2107; historic DOS API often limited to 2099. Access date granularity one day; modification 2s; create increments 10ms where supported. No stored timezone in classic FAT. Preserve unknown/reserved fields as applicable to explicit profiles.

## VFAT long filenames and aliases

VFAT is an optional directory extension to FAT12/16/32, not a separate allocation format. Windows NT 3.5 and Windows 95 adopted long names. Each LFN entry: 0x00:1 ordinal (0x40 marks last logical fragment, physically first); 0x01:10 five UTF-16 units; 0x0B:1 attr=0x0F; 0x0C:1 type=0; 0x0D:1 short-name checksum; 0x0E:12 six units; 0x1A:2 zero first cluster; 0x1C:4 two units. At most 20 records and 255 code units, physical sequence descends to 1 then short entry. Partial final fragment ends with 0x0000 then 0xFFFF padding; full fragment need not include terminator. Checksum over all 11 padded short-name bytes: start s=0, for each b set s=((s>>1)|(s<<7))+b modulo 256. Validate ordinal, checksum, terminator, padding and UTF-16; if invalid, expose only valid short alias or fail according to corruption policy, never fabricate a long name. Alias generation and collision handling are implementation/OS-specific. Preserve associated LFN records through rename/delete and detect orphaned entries. Historical UCS-2 terminology differs from UTF-16 surrogate handling. Short-case bits do not encode arbitrary mixed case.

## Historical extensions, metadata and derivatives

Classic FAT has no native ACLs, resource forks, compression, encryption or general transaction journal. DR-DOS, FlexOS and related multiuser DOS products implemented security extensions; SuperStor, Stacker, DoubleSpace and DriveSpace historically supplied volume compression; DR-DOS supplied optional volume encryption. These are separate compatibility profiles, not baseline capabilities. OS/2 FAT12/16 stores EAs in hidden EA DATA. SF referenced by directory field 0x14; FAT32 uses that word for cluster high bits, so FAT32.IFS uses separate EA. SF sidecar files and marks at 0x0C instead. Macintosh PC Exchange used FINDER.DAT and RESOURCE.FRK; macOS uses AppleDouble ._ files and .DS_Store; UMSDOS used --linux-.---. These are host conventions, not native FAT streams. DELWATCH pending-delete and IBM 4680/4690 distribution attributes repurpose fields; avoid writing unknown extensions. Human68K 18.3 names, TFAT and OEM variable root variants require independent profiles. FATX (Xbox 2001) uses incompatible boot and 64-byte directory records; Turbo FAT is a NetWare derivative. FAT+ draft (2007) is not baseline FAT16/32. Do not claim support or silently reformat any of these formats.

## Allocation, recovery and qualification

No general journal: mirrored FAT copies are not proof of atomicity. Build a reference map from valid directory trees, follow bounded chains, compare expected ceil(file_size/cluster_size) to actual allocation, distinguish zero-length files and directories, detect cycles, cross-links, orphan clusters, bad markers and inconsistent mirrors. Validate target identity and exact source bytes before relocation, reserve new clusters, copy and verify data, publish new links/reference and flush before freeing old allocation; interruption recovery must be explicitly designed and tested. Never run recovery against a guessed target. Free-space scans are linear; allocation hints, contiguous reservation, caching and multi-sector I/O can reduce fragmentation and metadata reads. Slack is unused tail space inside allocated clusters, distinct from external fragmentation. Formatting must solve FAT capacity and root geometry together, not merely write a type string. Test exact boundary counts, sector straddles, odd/even links, malformed BPBs, directory capacity, LFN collisions and corruption, full disks, truncated media, I/O failures and interrupted relocation. Historical recovery and undelete (0xE5) cannot guarantee content remains intact.
